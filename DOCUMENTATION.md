## 1. Executive Summary & Purpose

### 1.1 Executive Summary
**Process Chronicle** (also known as **Proof of Process**) is an enterprise-grade web application and REST API system designed to establish verifiable proof of authentic human authorship. By recording and analyzing the chronological development of written documents—from initial outline to final polished manuscript—Process Chronicle proves authentic human creation through the transparent historical evolution of text.

### 1.2 Purpose Statement
The primary purpose of Process Chronicle is to shift academic and professional evaluation away from opaque, post-hoc statistical AI detectors toward **process-based verification**. Rather than attempting to guess whether a static piece of text was generated by machine intelligence, Process Chronicle captures the natural, messy, iterative, and reflective process unique to human authorship.

### 1.3 Problem Statement
Current AI detection tools evaluate static documents *after* they are written, producing statistical probability scores using closed, black-box algorithms. These tools suffer from significant systemic flaws:
- **High False Positive Rates**: Non-native English speakers, highly structured technical writers, and formal academic papers are disproportionately flagged as AI-generated.
- **Lack of Actionable Evidence**: Statistical classifiers provide no context, explanation, or recourse for false flags.
- **Ignoring the Writing Process**: Real human writing involves brainstorming, structural re-organization, sentence rewrites, deletions, tone adjustments, and author reflection. Black-box detectors ignore this rich audit trail entirely.

Process Chronicle solves this by creating a structured audit trail of text evolution that highlights human decision-making and structural development over time.

## 2. Target Audience & Use Cases

### 2.1 Target Audience

| User Group | Description & Primary Need |
| :--- | :--- |
| **Academic Writers & Researchers** | Authors who need to verify the authenticity of research papers, dissertations, and grant applications. |
| **Students & Educators** | Students demonstrating genuine effort on essays, and educators seeking objective evidence of student writing growth. |
| **Journalists & Authors** | Content creators requiring verifiable attribution of human thought and investigation. |
| **Publishers & Editors** | Editorial boards looking for transparent verification of submitted manuscripts prior to publication. |

### 2.2 Key Use Cases & Scenarios

#### Scenario A: Academic Essay Verification
A university student writes an essay across three distinct stages: an initial outline, an expanded draft with structural changes, and a final polished manuscript. By loading these revisions into Process Chronicle, the student generates an objective AI-synthesized narrative summary detailing how arguments evolved, accompanied by a word-level diff and reflection log. This serves as proof of human authorship if questioned by academic evaluation tools.

#### Scenario B: Manuscript Editorial Audit
A non-native English researcher submits a peer-reviewed paper that was incorrectly flagged by a post-hoc AI detector due to formal syntax. Using Process Chronicle, the author provides their version history and reflection logs, demonstrating the step-by-step evolution of their research hypotheses and structural edits.

## 3. Main System Features

### 3.1 Chronological Version Tracking
- Multi-draft support allowing users to upload or paste up to 10 sequential document versions.
- Customizable version labels (e.g., *"Outline"*, *"First Draft"*, *"Peer Review Edits"*, *"Final Draft"*).
- Interactive timeline navigation enabling fluid inspection across different stages of writing.

### 3.2 Interactive Word-Level Diff Visualizer
- Side-by-side comparison engine highlighting exact word-level additions, deletions, and structural reordering between any two sequential drafts.
- Visual color coding (green for additions, red for deletions, muted text for unchanged passages).

### 3.3 AI-Powered Process Synthesis
- Server-side integration with Large Language Models (LLMs) via Django REST Framework.
- Evaluates structural shifts, topic expansions, sentence rewrites, and tone adjustments to construct a single, cohesive narrative paragraph outlining the writing journey.
- Supports **Google Gemini API** as the primary synthesis engine with automatic fallback to **OpenAI API**.

### 3.4 Author Reflection Logging
- Structured input fields allowing writers to articulate *why* specific changes were made (e.g., *"Rewrote intro paragraph to emphasize narrative hook"*).
- Integrates reflections into the LLM synthesis context to tie human intent directly to physical text changes.

### 3.5 Native `.docx` Document Import
- Built-in document parsing powered by `Mammoth.js`.
- Enables users to load `.docx` files directly into draft slots without manually copying and pasting plain text.

### 3.6 Privacy-Preserving Architecture & Local Caching
- **Stateless Server**: Draft content is never saved to a backend database; processing happens dynamically in memory.
- **Client Storage**: Portfolios, draft histories, and generated summaries are stored in browser `localStorage`.
- **Response Caching**: Generated process summaries are cached locally against content signatures to prevent redundant API calls and optimize token usage.

### 3.7 Printable Verification Reports
- High-contrast, printable portfolio layout formatted for PDF export or physical printing.

## 4. System Architecture & Technical Design

### 4.1 Architectural Overview

```
+-----------------------------------------------------------------------+
|                             USER BROWSER                              |
|                                                                       |
|   +---------------------------------------------------------------+   |
|   |                  React 19 / Vite Application                  |   |
|   |                                                               |   |
|   |  [Dashboard] ----> [Draft Editor] ----> [Portfolio View]      |   |
|   |        |                 |                      |             |   |
|   |  localStorage         Mammoth.js          Diff Engine         |   |
|   +---------------------------------------------------------------+   |
+-----------------------------------|-----------------------------------+
                                    |
                                    | HTTPS / REST Request
                                    | POST /api/generate-summary/
                                    v
+-----------------------------------------------------------------------+
|                           BACKEND SERVER                              |
|                                                                       |
|   +---------------------------------------------------------------+   |
|   |                    Django REST Framework                      |   |
|   |                                                               |   |
|   |   [Payload Validation] --> [Prompt Builder] --> [LLM Service] |   |
|   +------------------------------------------------------|--------+   |
+----------------------------------------------------------|------------+
                                                           |
                                       +-------------------+-------------------+
                                       |                                       |
                                       v                                       v
                        +----------------------------+          +----------------------------+
                        |     Google Gemini API      |          |        OpenAI API          |
                        | (google-generativeai SDK)  |          |       (openai SDK)         |
                        +----------------------------+          +----------------------------+
```

### 4.2 Frontend Architecture (React / Vite)
- **Framework**: React 19 operating inside Vite 8 for fast build times and hot-module replacement (HMR).
- **Router**: TanStack Router using strictly typed file-based route definitions (`src/routes/__root.tsx`, `index.tsx`, `create.tsx`, `portfolio.tsx`).
- **Styling System**: Tailwind CSS v4 paired with a custom dark-mode glassmorphism design system (`src/styles.css`).
- **State & Storage**: Client-side state managed via React hooks with automatic synchronization to `localStorage`.

### 4.3 Backend Architecture (Django REST Framework)
- **Framework**: Django 5.x running Django REST Framework (DRF).
- **Service Layer**: Decoupled LLM integration module (`backend/api/services/llm.py`) providing unified interfaces for Google Gemini (`gemini-2.5-flash` / `gemini-1.5-flash`) and OpenAI (`gpt-4o-mini`).
- **CORS Handling**: `django-cors-headers` middleware permitting cross-origin requests from frontend clients.

## 5. Installation & Setup Guide

### 5.1 System Prerequisites

Before deployment or local installation, verify that your environment satisfies the following software requirements:

- **Node.js**: Version `18.0.0` or higher (or **Bun** `1.0.0`+)
- **Python**: Version `3.10` or higher (tested up to `3.14.x`)
- **Package Managers**: `npm`, `bun`, or `yarn`, and `pip`
- **Git**: Installed for version control operations

---

### 5.2 Backend Installation (Django REST API)

1. Open a terminal and navigate to the project backend directory:
   ```bash
   cd backend
   ```

2. Create a clean Python virtual environment:
   ```bash
   # Linux / macOS:
   python3 -m venv venv

   # Windows (PowerShell):
   python -m venv venv
   ```

3. Activate the virtual environment:
   ```bash
   # Linux / macOS:
   source venv/bin/activate

   # Windows (PowerShell):
   .\venv\Scripts\Activate.ps1

   # Windows (Command Prompt):
   venv\Scripts\activate.bat
   ```

4. Upgrade `pip` and install all required dependencies:
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   ```

5. Run database migrations to prepare the Django environment:
   ```bash
   python manage.py migrate
   ```

6. Launch the backend development server:
   ```bash
   python manage.py runserver
   ```
   The backend API is now operational at `http://localhost:8000/`.

---

### 5.3 Frontend Installation (React / Vite Application)

1. Open a second terminal window at the root of the project (`process-chronicle/`):
   ```bash
   cd process-chronicle
   ```

2. Install Node modules using Bun or NPM:
   ```bash
   bun install
   # or
   npm install
   ```

3. Start the hot-reloading web development server:
   ```bash
   bun dev
   # or
   npm run dev
   ```

4. Access the web interface at `http://localhost:5173/`.

## 6. Configuration & Environment Setup

### 6.1 Backend Environment Configuration (`.env`)

Create a `.env` file in the `backend/` directory by copying `.env.example`:

```bash
cp backend/.env.example backend/.env
```

Configure the environment parameters as detailed in the table below:

| Environment Variable | Required | Default | Description |
| :--- | :--- | :--- | :--- |
| `SECRET_KEY` | **Yes** | None | Django secret key for cryptographic signing. |
| `DEBUG` | No | `True` | Enables detailed error pages during development. |
| `ALLOWED_HOSTS` | No | `*` | Comma-separated list of permitted host headers. |
| `GEMINI_API_KEY` | **Recommended** | None | Google AI Studio API key for Gemini models. |
| `OPENAI_API_KEY` | Optional | None | OpenAI API key used if Gemini API key is absent. |

---

### 6.2 Provider API Setup (Google Gemini & OpenAI)

#### Option A: Google Gemini API (Recommended)
1. Obtain an API key from [Google AI Studio](https://aistudio.google.com/).
2. Add the key to `backend/.env`:
   ```env
   GEMINI_API_KEY=AIzaSy...
   ```

#### Option B: OpenAI API (Fallback)
1. Obtain an API key from the [OpenAI Platform](https://platform.openai.com/).
2. Add the key to `backend/.env`:
   ```env
   OPENAI_API_KEY=sk-proj-...
   ```

## 7. User Manual & Operational Guide

### 7.1 Creating a Portfolio
1. Open the application in your browser (`http://localhost:5173/`).
2. On the main dashboard, click the **"Start a new portfolio"** button.
3. Enter your project title (e.g., *"Analysis of Cognitive Architectures in Modern Writing"*).

### 7.2 Managing Draft Iterations
1. The creation screen displays draft slots in chronological order.
2. Provide a descriptive label for each revision (e.g., *"Initial Outline"*, *"Draft 1"*, *"Peer Feedback Revisions"*, *"Final Draft"*).
3. Paste or type text into the respective content fields.
4. Click **"Add another draft"** to append additional iterations (minimum 2 drafts required).

### 7.3 Document Upload (`.docx`)
1. To import a Microsoft Word document directly into a draft slot, click **"Upload .docx"**.
2. Select the file from your local disk. `Mammoth.js` will parse the file formatting and populate the draft slot instantly.

### 7.4 Inputting Author Reflections
1. Scroll to the **Author's Reflection** section.
2. Detail key choices, structural shifts, or reasoning behind edits (e.g., *"In Draft 2, I removed section 3 because the argument was off-topic, and expanded on the core thesis in section 2"*).

### 7.5 Generating & Inspecting Process Summaries
1. Click **"Generate Portfolio"**.
2. The UI enters a loading state while sending the draft array to the backend.
3. Once processed, the application redirects to the **Portfolio View**, presenting:
   - The overall **Process Summary** generated by the LLM.
   - Author metadata and reflection summaries.
   - Interactive version tabs.

### 7.6 Utilizing the Word-Level Diff Visualizer
1. In the Portfolio View, navigate to the **Diff Visualizer** panel.
2. Select two draft versions to compare (e.g., *"Draft 1"* vs. *"Final Draft"*).
3. View word-by-word additions (highlighted green) and deletions (highlighted red).

## 8. API Reference Specification

### 8.1 Endpoint Details

#### `POST /api/generate-summary/`
Processes a structured set of sequential document drafts and optional author reflections, returning an AI-generated summary paragraph describing the evolution of the text.

---

### 8.2 Request Schema & Validation Rules

#### Request Headers
- `Content-Type: application/json`

#### Payload Schema (`JSON`)
```json
{
  "title": "String (Required)",
  "drafts": [
    {
      "label": "String (Required, max 100 chars)",
      "content": "String (Required, non-empty)"
    }
  ],
  "reflection": "String (Optional)"
}
```

#### Validation Rules
- **Minimum Draft Count**: At least `2` drafts must be provided.
- **Maximum Draft Count**: Maximum `10` drafts per payload.
- **Character Count Cap**: Combined text length across all drafts must not exceed `50,000` characters to prevent server exhaustion.

---

### 8.3 Response Schemas & Status Codes

#### Success Response (`200 OK`)
```json
{
  "summary": "Across 3 iterations, 'Analysis of Cognitive Architectures' evolved from an initial outline into a structured academic paper. Early revisions introduced core theoretical definitions, while subsequent drafts focused on refining tone and expanding empirical arguments. The writer's reflection underscores a deliberate restructuring in revision 2 to strengthen narrative flow."
}
```

#### Error Response: Validation Failure (`400 Bad Request`)
```json
{
  "drafts": [
    "At least two drafts are required to analyze changes."
  ]
}
```

#### Error Response: Missing Server Keys (`500 Internal Server Error`)
```json
{
  "error": "ConfigurationError",
  "message": "Neither GEMINI_API_KEY nor OPENAI_API_KEY is configured in the environment.",
  "details": "LLM API key is missing on the server. Please add GEMINI_API_KEY to your .env file."
}
```

#### Error Response: Upstream LLM Failure (`502 Bad Gateway`)
```json
{
  "error": "LLMApiFailure",
  "message": "Failed to generate summary: Service temporarily unavailable.",
  "details": "The LLM provider returned an upstream communication error."
}
```

---

### 8.4 Developer Code Examples

#### cURL Example
```bash
curl -X POST http://localhost:8000/api/generate-summary/ \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Sample Study",
    "drafts": [
      {"label": "Draft 1", "content": "Initial thoughts on thesis statement."},
      {"label": "Draft 2", "content": "Initial thoughts on thesis statement with expanded evidence."}
    ],
    "reflection": "Expanded thesis statement."
  }'
```

#### Python Example (`requests`)
```python
import requests

url = "http://localhost:8000/api/generate-summary/"
payload = {
    "title": "Sample Study",
    "drafts": [
        {"label": "Draft 1", "content": "Initial thoughts on thesis statement."},
        {"label": "Draft 2", "content": "Expanded thesis statement with supporting citations."}
    ],
    "reflection": "Added supporting citations."
}

response = requests.post(url, json=payload)
print(response.status_code)
print(response.json())
```

## 9. Troubleshooting & Frequently Asked Questions

### Q1: The backend throws a `500 Internal Server Error` when I click "Generate".
**Cause**: Neither `GEMINI_API_KEY` nor `OPENAI_API_KEY` is configured in `backend/.env`.  
**Resolution**: Open `backend/.env`, paste a valid `GEMINI_API_KEY` or `OPENAI_API_KEY`, and restart the Django server.

### Q2: CORS error in browser console when sending requests to backend.
**Cause**: The Django server is running on a host/port combination not allowed by CORS middleware.  
**Resolution**: Ensure `django-cors-headers` is installed and verify `CORS_ALLOW_ALL_ORIGINS = True` is set in `backend/core/settings.py`.

### Q3: `.docx` upload button is not loading text into the draft box.
**Cause**: The uploaded file may be corrupted or saved in an older binary `.doc` format rather than XML `.docx`.  
**Resolution**: Convert the document to standard Microsoft Word `.docx` format before uploading.
